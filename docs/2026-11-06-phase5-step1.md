# Phase 5.1 — synthetic-tone audio device (no DSP, no register access, no DMA)

Date: 2026-11-06. Result: **PASS**. "Internal Microphone" (manufacturer OhMyDSP, built-in) is a working CoreAudio input device fed by a timer-generated 1 kHz tone.
Hardware touched: none (the DMICProbe read-only probe still runs on load; dmic_p2 was unset).

## What worked
- Kext loads manually with `sudo sh tools/load-kext.sh` (`kmutil load -p`) after a one-time approval in Privacy & Security. Every rebuild changes the binary and asks for approval + restart again.
- Device/engine/stream/controls register; the Sound pane lists the device; engine start/stop follow CoreAudio's requests; the volume slider reaches the kext.
- `local/recordtest 5` (CoreAudio IOProc client): 471 calls, 241152 frames (expect ~240000), both channels peak 0.1500 (-16.5 dBFS) = 0.2 FS tone x gain 0.75. Zero HAL overload messages during the run.

## What failed on the way (and the real cause)
Symptom: device present, engine running, timestamps taken every wrap, but **zero IOProc calls** and coreaudiod logged an `overload` on every 10.7 ms cycle (`HAL_client_IO_duration` 0).
Root cause: **`convertInputSamples()` was not overridden.** The HAL's input read ends in `HALS_IOA1Engine::EndReading` -> `iokit_user_client_trap` into the engine, which calls `convertInputSamples`; Apple's base class returns `kIOReturnUnsupported`, and the HAL treats that as a permanent overload and never calls the client.
Found by `sudo sample coreaudiod` while a client was recording (IO thread stack showed `PerformIO` -> `EndReading` -> trap, then `IOWorkLoop_HandleOverload`), then reading IOAudioEngine.cpp.
Fix: engine override converts the S32 LE interleaved ring to the Float32 mix buffer (`src / 2^31`), bounds-checked.

Ruled out / changed along the way (kept, harmless): ring 1 MiB -> 128 KiB (16384 frames); setSampleOffset + setInputSampleOffset 2400 frames; `IOAudioEngineDisableClockBoundsCheck` (as AppleHDA); fixed clock domain. None of these was the cause. The runtime tunables (`tools/engine-tune`: tsmode, tick_ms) and the 2 s stat log line stay for the next steps.

## Side findings
- The unified log needs `/usr/bin/log`; plain `log` in zsh failed with "too many arguments" and `2>/dev/null` hid it (earlier "empty log" checks were invalid).
- One boot had no Apple audio devices (codec assertions at boot, before our kext loaded; earlier shutdowns had stalled). A cold power-off fixed it. Unload the kext before shutting down: `sudo sh tools/load-kext.sh unload`.
- The scratchpad is wiped on reboot; test tools live in `local/` (recordtest, engine-tune; git-ignored).
