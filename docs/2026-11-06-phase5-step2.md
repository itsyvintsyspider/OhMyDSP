# Phase 5.2 — DSPDevice refactor (Phase 2-4 hardware code as a reusable class)

Date: 2026-11-06. Result: **PASS** (identical hardware behaviour; live regression of the 4.5 capture through the new API).

## What changed
`bootDSP()` (one 620-line function with lambdas and gotos) is now `DSPDevice` (`src/DSPDevice.hpp/.cpp`):
`checkIdle`, `streamPrecheck`, `loadPipelineBlob`, `loadFirmware`, `powerUp`, `sendPipeline`, `startStream(mode, sd)`, `sample`, `stopDma`, `freeStream`, `teardown`.
Code was moved, not rewritten: same register order, masks, timeouts, log text. `DSPBoot.cpp` is now only the boot-arg harness (stage selection, timed 2 s measurement loop,
sample statistics, raw dump). Logging goes through a sink callback (`com_dmicmac_DMICProbe::dspLog`), so ioreg/os_log output is unchanged.
Step 5.3 will call the same methods from the audio engine (startStream mode 4, stopDma, freeStream).

Deliberate behaviour changes (none touches the passing path):
- Pipeline replay failure now ends the run as FAILED (the old code still reported FW_READY).
- PCM_PARAMS reply with a bad posn_offset now stops before DMA (the old code logged it and ran the DMA anyway).
- Missing/unexpected mailbox windows now abort instead of continuing to the stream stage.
- A stream whose RUN cannot be cleared still leaks its buffers on purpose; that decision now lives in `freeStream()`.

## Regression (tools: grep the "W ..." lines out of the registry log, compare with logs/phase4-5b-ioreg.txt)
1. **Dry run** (`dmic_p2=2 dmic_p3_n=19`, nothing written): 43 logged writes (power-up + teardown) identical in order/register/purpose to the 4.5b run's non-P3/P4 writes. Blob OK, firmware OK, 19/19 checked.
2. **Live** (`dmic_p2=1 dmic_p3_n=19 dmic_p4=5 dmic_p4_sd=5`): 
   - 507 writes, identical operation/register/purpose sequence to 4.5b (507). 5 values differ, all DMA bus addresses that change per boot (SD8 BDLPL/U, P4 BDLPL/U, page-table IOVA in the PCM_PARAMS mailbox word).
   - FW_READY, 19/19 accepted (error=0), rate 383.9 B/ms (4.5b: 384.1), 192080 words, non-zero 95937 (4.5b: 95934), guard-pattern words 0, final ADSPCS 0x00000f0f, 768320 bytes saved.
   - Capture content: right channel (mic B) live, left (mic A) exactly zero, as before. This time the user clapped: quiet floor about -38 dBFS with discrete bursts at -13 dBFS (0.6, 0.9, 1.2, 1.4, 1.9 s), clipping to full scale on the loudest. Not a glitch pattern. (Recording stays in local/, never committed.)
