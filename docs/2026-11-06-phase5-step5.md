# Phase 5.5: recovery, sleep/wake (2026-11-06)

Build: OhMyDSP 0.2.0, standalone variant loaded with `tools/load-kext.sh`. macOS 15.8.2, ThinkPad P1 Gen 3.
Hardware writes: the usual DSP power-up/stream writes only; the new `ROMDIAG` code is read-only.

## What was added
- Health check per tick: stall (no LPIB movement for 200 ms, `STALL_TICKS=40` at 5 ms) or an SD error status triggers `recoverLive`:
  stop DMA, tear the stream and DSP down, restart. At most 3 restarts per 60 s, then the engine gives up and
  delivers silence on a software clock until the application restarts the input.
- Wake: `checkIdle` retried 5 x 200 ms. Teardown moved into engine `stop()`.
- Test hook: `engine-tune inject=1` (one stall), `inject=2` (stall plus 3 refused restarts).
- Diagnostics (added after the failure below): on `ROM_STATUS INIT_DONE` timeout log `ROMDIAG` register snapshot
  (ROM status/error, ADSPCS, IPC regs, PCI cmd, CGCTL/PGCTL, HDA GCTL/INTCTL/STATESTS, SD8), then watch ROM_STATUS 3 s more
  and accept a late INIT_DONE.

## Results
| Test | Result |
|---|---|
| inject=1, 12 s recording | PASS: 2 recoveries of ~148 ms each, 1126 calls, full frames, no lost audio |
| inject=2, 12 s recording | PASS: engine gave up and delivered silence, no hang, no overload (535552 frames, 273408 non-zero = audio before the fault) |
| 132 s continuous run, then stop | PASS: channel B live in 66 of 67 windows (first window warm-up), stop clean (DMA stop OK, stream free clean, DSP down) |
| Cold boot, idle sleep/wake, then record | PASS (238080 frames before, 237568 after; real signal both times) |

| Unload during a 12 s recording | PASS: recording ended early (181248 frames, ~3.8 s) with real audio (peak -10.5 dBFS), no hang; engine stop clean (DMA stop OK, stream free clean, DSP down). The earlier all-zero run did not reproduce. |

## Failure seen once (not reproduced)
Earlier in the same boot (after the 132 s session, an unload/reload and a sleep) every DSP start failed:
`poll ROM_STATUS INIT_DONE TIMEOUT (last 0x00000011, mask 0xffffff want 0x1)` at 11:29:05 (during sleep entry),
11:31:06 and 11:31:28 (after a fresh kext load post-wake). 0x11 = `CSE_IMR_GRANTED`: the ROM stays in the CSE handshake.
Teardown after each failure was clean (ADSPCS back to 0x00000f0f). All starts before the sleep reached 0x05000001 then FW_ENTERED 0x5.
Register differences against the last good start: `GCTL` 0x001 instead of 0x101 (first failure only), `CGCTL=0x007b09ff` and `PGCTL=0`
instead of 0x0 / 0x1b (PCI config registers reset by the sleep). Same ROM_CONTROL command as in good starts.
Not reproduced after a full power-off with one idle sleep/wake and one sleep during recording. Cause unknown; the trigger depends on earlier
state in the boot, not on sleep alone. A cold boot recovers it (full power-off).

## Fixed
- `failStarts` (inject=2) was not cleared at the give-up path, leaving 2 refusals pending for the next application start. Now cleared there.

## Open
- The post-sleep ROM failure (stuck at 0x11) is unexplained and did not come back in 5 further sleep/wake cycles (3 idle, 1 during recording, 1 after unload/reload) across two cold boots. `ROMDIAG` is in place to capture it if it returns.
- If it returns: the driver fails the start cleanly; the recovery path covers mid-stream faults only, not a ROM that never boots. A full power-off recovers.
