# Phase 6.1a: core kext without IOAudioFamily (2026-11-06)

Goal: make the part that talks to the DSP injectable into the OpenCore Boot KC (no IOAudioFamily, which lives in the System KC), and expose
the capture ring to userspace. Audio conversion (mic join, gain) and the CoreAudio device move to userspace (6.1c).

## Why not a user client for the HAL plug-in directly
`/System/Library/Sandbox/Profiles/com.apple.audio.coreaudiod.sb` only allows `iokit-open` for `IOAudioControlUserClient`, `IOAudioEngineUserClient`,
`IOAudio2DeviceUserClient`, `RootDomainUserClient`, `IOUserUserClient` (or classes with a sandbox extension). A custom user client is blocked
inside coreaudiod, so the architecture is kext -> root LaunchDaemon (opens the user client) -> Mach service -> AudioServerPlugIn.

## Implemented
- `ohmydsp/include/OhMyDSPShared.h`: kernel/user contract (memory type 0 = DMA ring, 1 = status page; methods start/stop/tune).
- `Capture.cpp/hpp` (`OhMyDSPCapture`): bring-up, 5 ms position tick, health check and recovery (same policy and log texts as the IOAudio engine).
- `UserClient.cpp/hpp`: root only (`kIOClientPrivilegeAdministrator`), one client at a time, stops the stream when the client goes away.
- Build: `make CORE=1 LILU=0|1` -> `build/core-standalone`, `build/core-lilu` (`-DOHMYDSP_CORE`, no IOAudioFamily library, `IOUserClientClass` in the personality). `tools/load-kext.sh core`.
- Test client `tools/coretest.c` (`local/coretest [secs] [out.wav] [inject]`).

## Bugs found on the way
- First run: positions never moved. The tick timer was created with the work loop as owner instead of the capture object, so the callback never ran its cast. Fixed.
- `tune()` passed `this` as an extra `runAction` argument, shifting key/value (inject returned kIOReturnBadArgument). Fixed.

## 6.1c prepared (not yet run)
`ohmydsp/userspace/` (`make -C ohmydsp/userspace`): `ohmydspd` (root daemon, kext user client -> XPC shared memory copy of the ring, 2 ms pump,
peer must be root or `_coreaudiod`) and `OhMyDSP.driver` (AudioServerPlugIn, "Internal Microphone", Float32 2 ch 48 kHz, mic join + fixed +9 dB).
Offline harness check of the driver's property/IO entry points passed. Kext gained `epoch` in the status page and monotonic laps across recovery.
Install: `sudo sh tools/install-userspace.sh` (no approval, no reboot); daemon-only test: `sudo local/daemontest`.

## 6.1c results (2026-11-06, same boot, kext with epoch)
- `sudo local/daemontest 4`: start reply 147 ms, 192184 frames in 4.00 s (expected ~192150), 11 laps, epoch 1, channel B live, stop OK. XPC shared memory works.
- `sudo sh tools/install-userspace.sh` (needed `mkdir -p` of `/Library/Audio/Plug-Ins/HAL`, fixed): driver loaded by coreaudiod into `com.apple.audio.Core-Audio-Driver-Service`
  (pid 1137), `initialized`, `StartIO -> 0`. The XPC Mach lookup and shared-memory mapping work inside the driver sandbox.
- `local/recordtest 5 OhMyDSP`: device "Internal Microphone" by OhMyDSP, 239616 of ~240000 frames, rms -14 dBFS. System Settings > Sound > Input lists it, level meter moves.
- Raw peaks near 0 dBFS are loud transients in the room/keyboard (first 100 ms block is -82 dBFS, median block peak -24 dBFS), not a startup artifact.
- Observed: macOS registers the daemon as a background item (notification + Login Items); AMFI logs "adhoc signed ... not valid" but the daemon still runs on this Intel setup (compatibility note for stricter setups).
