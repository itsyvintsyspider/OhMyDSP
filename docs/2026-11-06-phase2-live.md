# 2026-11-06 — Phase 2 LIVE run (dmic_p2=1): DSP firmware booted to FW_READY

Status: **Phase 2 succeeded on first live run.** No panic/hang. Raw: `logs/phase2-live-ioreg.txt`. Dry run: `2026-11-06-phase2-dryrun.md`.
Setup: USB OpenCore, Phase 2 build, boot-args `-v debug=0x100 keepsyms=1 alcid=31 -igfxblt -igfxbls -igfxmlr dmic_p2=1`,
firmware sof-bin v2026.09.2 `intel-signed/sof-cnl.ri` (sha256 c5119cfc…359e).

## Observed (register values)
- Power-up: ADSPCS SPA cores0-3 -> CPA 0x0f0f0f0f. ROM_CONTROL HIPCIDR=0x81004200 accepted: HIPCIDA.DONE set (0x80000000).
- Core0 leave reset/unstall OK (ADSPCS 0x0f0f0e0e); cores1-3 powered down (CPA 0x01010e0e = core0 only).
- ROM_STATUS = 0x05000001 (INIT_DONE) before DMA; after code-loader DMA (SD8 tag 2, 35 BDL entries, 557056 B) ROM_STATUS = 0x5 (FW_ENTERED),
  ROM_ERROR = 0.
- HIPCTDR = 0xf0000000 -> FW_READY message: size 108, cmd 0x70000000, **version 2.2.0, ABI 0x03016001 (3:22:1)**; acked via HIPCTDR/HIPCTDA.
  dspbox/hostbox offsets in the message read 0 (windows come from the extended manifest; unchanged from recipe).
- Teardown clean: SD8 reset, BDL/CBL/SPIB cleared, PPCTL decouple bit cleared, DSP powered down; final ADSPCS = 0x00000f0f (= idle baseline).
  PGCTL 0x1b / EM2 0x84806000 / CGCTL 0 restored.

## What this proves
- A non-AppleHDA driver can run the ROM handshake and code-loader DMA from stream SD8 (tag 2) while AppleHDA owns SD0/1/7.
- DMA via IODMACommand (IOVA 0xa1afb1000) works under this OpenCore/VT-d config; polling works, interrupts not needed for boot.
- Same 2.2.0 firmware that ran under Linux boots under macOS.
